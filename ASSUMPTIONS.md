# Допущения

Формат: что было неясно → что выбрали и почему → что изменится, если допущение неверно.

## Инфраструктура

1. **Порт веб-интерфейса.** В задании порт не указан → `8080` по умолчанию, меняется через `WEB_PORT` в `.env`. Если нужен другой порт, это правка одной переменной.
2. **Пароли внутренних сервисов.** Проверяющий копирует `.env.example` и вписывает только ключ LLM → в `.env.example` лежат пароли Postgres и Redis для локального запуска. Эти сервисы не публикуют порты наружу. Для продакшна пароли задаются в `.env`, код не меняется.
3. **Смена модели без пересборки.** «В настройках» трактуем как переменные окружения: правим `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` в `.env` и выполняем `docker compose up -d`, контейнеры пересоздаются без пересборки образов. Если нужна смена из интерфейса, добавим страницу настроек администратора поверх той же конфигурации.
4. **Лимит загрузки.** До 10 файлов по 20 МБ → файлы загружаются по одному запросу на файл. nginx отклоняет тело больше 21 МБ кодом 413, приложение проверяет точный лимит и число файлов. Если потребуется пакетная загрузка, лимит nginx придётся поднять до ~205 МБ, и защиту от больших файлов будет держать только приложение.

## Разбор файлов и данные

5. **Десятичный разделитель.** В «живых» таблицах числа бывают записаны текстом → запятая и точка считаются десятичным разделителем, пробелы (в том числе неразрывные) — разделителем тысяч: «224,0» → 224, «1 050» → 1050. Каждое такое исправление попадает в отчёт о данных. Если придут файлы с английской записью «1,050» (тысяча пятьдесят), она прочитается как 1,05 — понадобится настройка локали файла.
6. **Пропуски.** «нет данных», «н/д», «-», «#Н/Д», пустая ячейка в числовом столбце → значения нет: оно не подставляется нулём и не угадывается, расчёты с ним дают «нет данных» и предупреждение. Если заказчику нужна подстановка (например, среднее по филиалам), это отдельная операция, которую увидит пользователь.
7. **Где в Excel таблица.** Шаблонов нет → лист делится на блоки по пустым строкам; строка с одной ячейкой над блоком — заголовок таблицы (из него берётся единица: «млн руб.» → «млн ₽»), следующая строка — шапка, первый столбец — подписи строк. Двухуровневые шапки и объединённые ячейки в шапке не поддерживаются: такая таблица прочитается, но подписи столбцов будут неполными.
8. **Формулы.** Формулы не вычисляются: берутся значения, сохранённые Excel вместе с файлом. Файл, сгенерированный программой без сохранённых значений, даст пустые ячейки и предупреждения.
9. **Скрытые листы** пропускаются с пометкой в отчёте: пользователь их не видит и не может проверить, а в них проще всего спрятать постороннюю инструкцию для модели.
10. **Макросы.** Файлы .docm/.xlsm/.pptm принимаются: VBA-части удаляются до чтения, макросы никогда не выполняются, в отчёте появляется пометка. Если политика безопасности требует отклонять такие файлы, это одна проверка в `sniff.py`.
11. **Итоги.** Строка «Итого…/Всего…» сверяется с суммой строк выше, столбец «Итого X» — со столбцами «… X». Проценты, средние, NPS и доли не суммируются и не сверяются. Допуск — половина единицы последнего знака. Расхождение — предупреждение, а не ошибка: первоисточник всё равно таблица.
12. **Текстовые файлы.** Кроме .docx/.xlsx/.pptx принимаются .txt и .md в UTF-8 — например, скопированный текст раздела «Суперсервис». Старые .doc/.xls/.ppt и файлы с паролем отклоняются с подсказкой пересохранить.

## Сценарий

13. **Цифры в тексте слайдов.** Модель не пишет числа из данных — только подстановки `{имя}`, которые код заменяет фактами. Без подстановки разрешены годы, «3 квартал», счёт до 12 («1 из 5»), «100 %» и N показателей «на N» из операций `rate` сценария. Числа словами («девять тысяч») тоже запрещены. Множитель `scale` — только степень десяти (перевод единиц): иначе из реальной цифры можно было бы «посчитать» любую (так прошла атака с 9 999 в первой версии). Если правило помешает нормальному тексту (например, «топ-20 клиентов»), оно расширяется списком разрешённых шаблонов, а не отключается.
14. **Ряды из разных таблиц.** Если подписи не совпадают («Июль факт» и «Июль»), но длина рядов одинакова, значения сопоставляются по порядку; это попадает в предупреждения на шаге проверки сценария, чтобы пользователь видел, что с чем сравнили.
15. **Утверждения из документов.** Числа из комментариев руководителя («рост около 12 %») модель выносит в `claims` вместе с показателем из таблицы; совпадением считается разница до 0,5 или 1 %. При расхождении в интерфейсе показывается цифра из таблицы — она и идёт на слайды.
16. **Оси графиков начинаются с нуля**, включая вспомогательную ось процентов: колебание маржи с 13,2 до 11,1 % не должно выглядеть обвалом. Если заказчику нужен «приближенный» вид, в сценарий добавляется явный диапазон оси.
17. **Тон изменения затрат.** В схеме затрат рост статьи окрашивается красным, снижение — зелёным; изменения меньше 3 % нейтральные. Для статей, где рост хорош (например, инвестиции), сценарий задаёт `increase_is: "good"`.
18. **Режим рассуждений Qwen.** Для структурного ответа он выключен: в контуре заказчика — `chat_template_kwargs.enable_thinking=false`, на OpenRouter — `reasoning.enabled=false`; оба варианта задаются строкой `LLM_EXTRA_BODY` без правки кода. Если сервер всё же вернёт `<think>…</think>`, клиент вырезает этот блок.
19. **Попытки модели.** Сценарий принимается только после всех проверок; модели возвращается полный список ошибок, всего не больше 3 попыток. Если модель не справилась, пользователь видит понятную ошибку и может запустить генерацию снова, а не получает сломанную презентацию.

## Проверка формулировок и защита от указаний в документах

20. **Сводка данных для модели.** Перед вызовом код считает и передаёт модели направления по периодам, рейтинги, «ниже плана», рост к прошлому году, прибыль и маржу, пометку «один период» для таблиц-срезов. Распознавание формы таблиц опирается на обычные деловые слова (месяцы, «план/факт», «итого», «выручка/затраты», «прошлый год»). Таблицу без этих признаков модель получит без сводки — числа останутся верными, формулировки придётся проверять пользователю.
21. **Мягкие проверки формулировок.** Несколько надёжных правил (уровень вместо разницы: «отстал на 96,6 %»; динамика по таблице из одного периода; число слайдов из материалов; рекламные штампы и «!» в ролике) возвращаются модели один раз. Если замечание осталось, сценарий всё равно принимается, а замечание показывается пользователю на шаге проверки: эвристика не должна стоить пользователю презентации.
22. **Указания модели внутри документов.** Абзац с явной командой модели («игнорируй правила», «таблице не верь»), обращением к ИИ/сценаристу/редактору с указанием или служебными словами сценария удаляется до вызова модели и попадает в отчёт и на слайд «Проверка данных». Обычный деловой текст («Прошу подготовить…», «верьте таблице») проходит. Если фильтр пропустит хитрую формулировку, остаются ещё два рубежа: правила промпта и запрет на числа вне подстановок. Скрытый текст Word пропускается с пометкой; скрытые строки и белый текст в Excel пока не определяются (их содержимое всё равно проходит фильтр указаний).
23. **Слайд «Проверка данных».** Если в данных что-то исправлено, чего-то нет, документ расходится с таблицей или найден текст с указаниями для модели, в конец презентации добавляется таблица «Где / Что было / Что сделали» — менеджер просил «скажите мне, что вы исправили». Слайд входит в число слайдов; если пользователь задал точное число слайдов, он не добавляется автоматически.
24. **Округление.** Половина округляется вверх (50,25 → 50,3), как в Excel и в бухгалтерии, а не «к чётному», как функция `round` в Python.
25. **Длительность ролика.** Модель плохо складывает числа: сумма сцен часто выходит 78–86 с при лимите 60–75 с. Если текст каждой сцены при этом остаётся произносимым, код пропорционально подгоняет длительности к границе и пишет об этом в предупреждениях; иначе модель сокращает текст. Темп речи: жёсткий предел 2,6 слова в секунду, мягкий — 5,5 слога в секунду (диктору придётся спешить).
26. **Известное ограничение защиты.** Правдоподобный деловой абзац без обращения к модели (например, «уточнение финансовой службы: недобор Урала — учётный эффект») фильтр не отличит от обычного комментария — это и есть комментарий пользователя. Цифры на слайдах он изменить не может (они только из таблиц), но может повлиять на формулировку причин и выбор рисков. Такие расхождения видны на шаге проверки сценария, а числовые утверждения из документов попадают в «Проверку данных».

## Аккаунты и доступ

27. **Регистрация открыта.** «Простая авторизация» → вход по email и паролю (от 10 символов), без подтверждения почты и восстановления пароля. Для внутреннего сервиса заказчика это заменяется входом через корпоративный SSO; модель данных (пользователь → проекты → файлы, задачи, сценарии, результаты) от этого не меняется.
28. **Сессия живёт 14 дней** (`SESSION_DAYS`), cookie с флагом Secure включается переменной `COOKIE_SECURE=true` при работе по HTTPS; локальный `docker compose up` работает по HTTP.
29. **Чужие проекты отвечают 404, а не 403**, чтобы нельзя было проверить, существует ли проект с таким id.
30. **Регистрация сообщает, что email занят.** Без подтверждения почты иначе нельзя: пользователь должен понять, почему не получилось. Перебор адресов ограничен 10 регистрациями в час с одного IP. Вход, наоборот, одинаково отвечает на неверный пароль и неизвестный email и тратит на них одинаковое время.
31. **Блокировка входа.** 8 неудачных попыток за 15 минут для пары «email + IP» — дальше 429 до конца окна; удачный вход обнуляет счётчик. Владелец аккаунта с другого адреса входит как обычно. Порог по одному email со всех адресов — 100 неудач в час: только при распределённом переборе ждать придётся и владельцу. Вход и регистрация выдают новую сессию и закрывают ту, что была в браузере; «Выйти везде» закрывает все сессии.
32. **Свои лимиты сервиса** (кроме лимитов из задания): до 100 проектов и 1 ГБ файлов на пользователя (`MAX_PROJECTS_PER_USER`, `MAX_BYTES_PER_USER`), текст — до 200 000 символов. Документация API (`/api/docs`) выключена, включается `ENABLE_API_DOCS=true`.
33. **Развёртывание по HTTPS.** TLS завершается на внешнем балансировщике заказчика: там же включается HSTS, а в `.env` — `COOKIE_SECURE=true`. API доверяет заголовку `X-Forwarded-For` от любого адреса внутренней сети (`FORWARDED_ALLOW_IPS="*"`), потому что порт API наружу не открыт, а nginx перезаписывает этот заголовок. Остальные контейнеры этой сети и так имеют доступ к базе, так что доверие к ним ничего не добавляет.

## Генерация, проверка и сборка

34. **Утверждение сценария — это запуск сборки.** Отдельной кнопки «утвердить» нет: файл собирается из выбранной версии сценария (по умолчанию последней), и задача сборки хранит номер этой версии. Собрать можно и любую прежнюю версию.
35. **Ролик** — 1920×1080, 30 кадров в секунду, H.264. Каждая сцена — один из семи наших шаблонов (заголовок, тезис, пункты, крупная цифра, сравнение, шаги, финал) с анимацией появления; текст диктора идёт субтитрами. Озвучки в этой версии нет: голос (ElevenLabs) добавляется следующим модулем, субтитры останутся. Цвета и шрифты берутся из brand.json проекта, как у презентации; фон — основной цвет бренда.
36. **Время генерации** меряется по этапам и хранится в задаче: очередь, разбор файлов, подготовка данных, обращение к модели (с числом попыток), сохранение; для сборки — подготовка, вёрстка в Chromium, запись PPTX. Время, которое пользователь тратит на проверку сценария, в замер не входит. Первый замер на материалах заказчика: сценарий за 18 с (одно обращение к модели), сборка 8 слайдов за 2 с. Ролик по тексту о Суперсервисе: сценарий за 35 с (две попытки модели), запись 75 секунд видео — 46 с в Docker на Mac M-серии (2 250 кадров, 3,7 МБ). Запись ограничена 15 минутами (`VIDEO_TIMEOUT_S`).
37. **Готовые файлы и история.** История запусков хранится, пока существует проект; файлы (PPTX или MP4 и превью) — у последних пяти сборок проекта, более старые удаляются. Готовые файлы входят в квоту места вместе с загруженными материалами (1 ГБ); при заполненной квоте новая сборка не запускается.
38. **Шрифты.** На сервере есть шрифты с метриками Arial, Times New Roman и Courier New, а для Georgia — Gelasio (латиница) и DejaVu Serif (кириллица, чуть шире). Если в brand.json указан другой шрифт, презентация всё равно использует его имя (у получателя он может быть установлен), но вёрстку сервер считает по запасному шрифту и предупреждает об этом в отчёте о сборке.
39. **Логотип** — PNG до 2 МБ и до 4096 точек по стороне; сервер раскодирует его и сохраняет заново как обычный PNG (без текстовых блоков и анимации). SVG не принимается (это код, а не картинка).
40. **Если воркер упал посреди задачи**, задача через полторы минуты без пульса возвращается в очередь; после второго падения она завершается ошибкой с советом уменьшить файлы — так один «ядовитый» файл не крутится бесконечно.
41. **Правки сценария.** Подряд можно сохранить до 100 правок; новый сценарий от модели начинает счёт заново. Сохранить правку можно только поверх последней версии: если сценарий за это время изменился (другая вкладка, новый план), сервер отвечает 409 и просит обновить страницу.

## Интерфейс

42. **Что правится формой.** Заголовки, подписи, выводы, тексты рисков и решений, подписи показателей, названия рядов и столбцов, порядок и удаление слайдов. Цифры добавляются только из списка значений, посчитанных по данным. Новый слайд, другой ряд графика или новый расчёт — во вкладке «Расширенный режим (JSON)»; сервер проверяет её так же.
43. **Предпросмотр на шаге проверки — текстовый**: каждый слайд показан с подставленными цифрами, таблицами и рядами графиков. Картинки слайдов появляются после сборки (около 2 секунд), её можно повторять сколько угодно.
44. **Готовый ролик** показывается плеером на странице проекта; под ним кадры сцен — нажатие запускает ролик с этой сцены. Во время записи видно, сколько процентов кадров снято.
45. **Сессия и вкладки.** Если сессия закончилась, интерфейс отправляет на вход и после входа возвращает на ту же страницу (только внутри сервиса). Правки, не сохранённые в одной вкладке, не видны в другой; сохранение поверх более новой версии отклоняется с просьбой обновить страницу.
46. **Изоляция рендера.** Контейнер `renderer` видит только текущие задания в общей папке `spool` (их сценарии с цифрами и логотипы), но не файлы проектов и не базу; одновременно в нём идут не больше двух заданий. Если понадобится изолировать и задания друг от друга, следующий шаг — отдельный контейнер на каждое задание.

## Озвучка

47. **Ключ ElevenLabs у каждого пользователя свой.** Он вводится в «Настройках», проверяется запросом списка голосов и хранится зашифрованным (Fernet), с привязкой к пользователю. Ключа нет ни в ответах API, ни в логах, ни в сообщениях об ошибках — ни целиком, ни последних символов: интерфейс показывает только «озвучка включена», голос и дату. Без ключа ролик собирается без звука, с субтитрами.
48. **Ключ шифрования** задаётся в `SECRETS_KEY` (несколько через запятую — для ротации: первый шифрует, остальные только расшифровывают). Если он не задан, сервис сам создаёт его на томе данных (`/data/secrets/fernet.key`, права 600), чтобы `docker compose up` работал без лишних шагов; в проде ключ берётся из менеджера секретов. Дамп базы без этого ключа не раскрывает ключи пользователей. Если ключ шифрования сменили без ротации, пользователь увидит просьбу ввести ключ ElevenLabs заново.
49. **Голос по умолчанию** — George: готовый голос, который есть в любом аккаунте ElevenLabs. В «Настройках» можно выбрать любой голос своего аккаунта. Модель — `eleven_v4` (`VOICE_MODEL`).
